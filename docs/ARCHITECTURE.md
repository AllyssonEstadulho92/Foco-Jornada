# Arquitetura

Atualizado em: 2026-09-17. O histórico integral anterior foi preservado em `docs/history/ARCHITECTURE-pre-217.md`.

## Plataforma e camadas

Uma PWA React 19/TypeScript 5.9/Vite 7/React Router, publicada em GitHub Pages. AppShell responsivo (desktop sidebar, mobile top bar/bottom nav/drawer); o mesmo bundle e perfil servem todos os dispositivos. Domain isolado para férias/jornada/horas; aplicação coordena casos de uso, presentation renderiza componentes e Zustand agrega registos de horas. IndexedDB/Dexie e `secureStorage` fazem parte do cofre cifrado AES-GCM; replicação opcional por Cloudflare Worker/Durable Object transporta cofre cifrado, não passwords/PIN/dataKey.

## Rotas hash e saltos internos — PR #218

`router.tsx` usa `createHashRouter`, portanto o fragmento do endereço (`#/ferias`) identifica a rota. Um `<a href="#vacation-evidence-title">` introduzido no PR #217 substituía essa rota e originava `404 Not Found` no Router, reproduzindo a captura real do iPhone. O atalho da vista geral usa agora `button` e `focusSection(id)` (`src/presentation/navigation/focusSection.ts`) para deslocar até ao título e mover o foco sem modificar o URL. O título tem `tabIndex={-1}`. `router.tsx` regista ainda a rota residual `*` que apresenta `NotFoundPage` com ações locais de recuperação em vez da mensagem de desenvolvimento. CSS `vacation-evidence-layout.css` conserva a aparência do atalho; `route-not-found.css` define o cartão adaptativo. `focusSection.test.ts` usa jsdom para provar que o hash não muda, e `vacation-evidence.test.ts` protege a navegação e fallback. **Pendência separada:** o skip link global em `AppShell` usa `href="#main-content"` e tem risco idêntico; corrigir de forma dirigida, não presumir que esta alteração o resolveu. Ver `docs/HASH-ROUTER-NAVIGATION.md`.

## Férias — rotas, apresentação e dados

`#/ferias` → `VacationWorkspacePage(view="overview")` → `VacationBalancePage` + `VacationEvidencePanel` (apenas overview). `#/ferias/planeamento` → mesmo `VacationBalancePage` com secções não aplicáveis ocultas via CSS; `VacationPlannerPanel` mostra resumo vivo, `VacationSuggestionsPanel`, `VacationJointPlanner`, calendário/simulação. **Limite atual:** a vista ocultada continua montada; não alegar que o isolamento CSS evita toda a computação.

CSS de layout `vacation-workspace.css`, `vacation-evidence-layout.css`, `vacation-evidence.css` e módulos já existentes `vacation.css`, `vacation-accrual.css`, `vacation-insights.css`, `vacation-planner.css`, `vacation-planner-live.css`, `vacation-suggestions.css`, `vacation-joint-planner.css`. PR #219 adiciona `vacation-visual-audit.css`, importado por último em `VacationWorkspacePage` e com todos os seletores restringidos a `.vacationWorkspace`; é uma camada de harmonização dos dois ecrãs, não substitui lógica nem altera as regras de visibilidade base. Dois separadores mobile em grelha compacta, cards com altura intrínseca, foco tipográfico no saldo, densidade visual consistente e atalho de proveniência secundário. Teste `src/styles/vacation-visual-audit.test.ts` protege separação, hash e regras de acessibilidade; limitações e evidências em `docs/VACATION-UI-AUDIT-2026.md`. A consolidação futura das camadas CSS deve aguardar captura real e regressões.

`VacationBalance.ts` é a autoridade para referência laboral e projeção pessoal. Meta anual pessoal configurável (28 por omissão): acumulado vivo calculado diretamente da meta, meses anteriores e fração do mês local; saldo vivo = acumulado + transitados + ajustes − gozadas, saldo após planeadas subtrai dias úteis futuros. Contagem normaliza datas civis, deduplica e desconta seg.–sex. por defeito; dias manuais sem data continuam descontados, não são transformados em datas individuais.

`VacationYearRecords.ts` lê `useWorkHoursStore` (`reason="ferias"`), `foco-jornada-shift-map-v1-AAAA-MM` e `foco-jornada-payroll-plan-v1-AAAA-MM` (registos `kind="vacation"`) através de leitura injetada do cofre. `collectVacationEvidenceForYear` valida YYYY-MM-DD, reúne a proveniência única ordenada (`horas`, `turnos`, `plano`); `collectVacationDatesForYear` deriva as datas dessa mesma coleta para o planeador do ano seguinte. Uma data válida no mesmo ano encontrada numa folha de outro mês é mantida. `VacationEvidencePanel` lê essas fontes somente quando o detalhe está aberto, não escreve e oferece refresh manual, além de foco/visibilidade. A página do ano corrente ainda tem coletor próprio: reconciliar depois de testes, não pressupor equivalência em fonte cifrada indisponível.

## Segurança, riscos e QA

PR #217, correção #218 e CSS proposto #219 não alteram autenticação, autorização, sessões, CSRF, backend, esquema de dados, Worker, segredos, dependências ou mecanismo de sync; não usam HTML injetado, não gravam nem enviam pedidos de férias. Links de rota usam `NavLink`; saltos internos do Router não devem utilizar hashes simples. Botões têm foco visível, painel de origens `aria-expanded`/`aria-controls`, painel oculto `[hidden]`, contraste forçado e movimento reduzido. Testes `VacationYearRecords.test.ts`, `vacation-evidence.test.ts`, `focusSection.test.ts`, `vacation-visual-audit.test.ts` cobrem fontes duplicadas/indisponíveis, navegação, datas, foco e invariantes CSS. CI: auditoria, TypeScript, ESLint, Vitest, build, Worker dry-run e smoke Chromium. Testes físicos cross-device pendentes.

Feriados, escalas diferentes de segunda–sexta, aprovação, disponibilidade da parceira e valores contratuais requerem confirmação externa. Ver também `docs/VACATION-EVIDENCE.md`, `docs/VACATION-PLANNER-LIVE.md`, `docs/VACATION-PLANNER.md` e `docs/VACATION-SUGGESTIONS.md`.
